# Phase 4 Core deployment preparation (preserved)

> The first hosted release now targets the legacy PRE APIM. Use
> `pre-release-readiness.md` and `infra/parameters/pre-legacy.bicepparam` for
> that release. This document and `infra/parameters/pre.bicepparam` preserve the
> separately prepared Core configuration and must not be used for legacy PRE.

Phase 4 prepares, but does not execute, the deployment of the standalone APIM
Developer Portal. The managed APIM portal remains available throughout rollout.

## Proposed Azure resources

All resources are parameterized and default to `rg-common-core` in Spain Central:

| Resource | PRE default | Purpose |
| --- | --- | --- |
| Static Web App | `apb-apim-portal-pre` | Vue 3 SPA |
| Linux App Service | `apb-apim-portal-bff-pre` | .NET 8 BFF |
| App Service plan | `asp-apb-apim-portal-bff-pre` | B1 non-production compute |
| Log Analytics workspace | `log-apb-apim-portal-bff-pre` | Application telemetry store |
| Application Insights | `appi-apb-apim-portal-bff-pre` | BFF observability |
| APIM role assignment | deterministic GUID | Reader at the exact `apim-cmn-core` resource |

The BFF App Service uses a system-assigned managed identity, HTTPS-only native
.NET 8 Linux hosting, `/healthz`, HSTS, HTTP/2, TLS 1.2 minimum, FTPS disabled,
restricted CORS, and production JSON console logging. No Docker image is needed.

The templates do not modify APIM. They create only the reader role assignment at:

`/subscriptions/8b72e64a-ae1a-4ac3-9960-dda8ee63d59e/resourceGroups/rg-common-core/providers/Microsoft.ApiManagement/service/apim-cmn-core`

using API Management Service Reader role
`71522526-b88f-4d52-b57f-d31fc3546d0d`.

## Human approvals before deployment

Confirm the resource group, region, globally unique SPA/BFF names, Static Web
Apps SKU, App Service plan SKU/cost, public network exposure, telemetry retention,
single-tenant Entra model, and whether the organization permits deployment-token
retrieval for Static Web Apps. The defaults are proposals, not approved names.

## Bicep validation and deployment commands

Run a what-if first. These commands are documentation only and have not been
executed:

```powershell
az deployment group what-if `
  --subscription 8b72e64a-ae1a-4ac3-9960-dda8ee63d59e `
  --resource-group rg-common-core `
  --name apim-portal-pre-bootstrap `
  --template-file infra/main.bicep `
  --parameters infra/parameters/pre.bicepparam

az deployment group create `
  --subscription 8b72e64a-ae1a-4ac3-9960-dda8ee63d59e `
  --resource-group rg-common-core `
  --name apim-portal-pre-bootstrap `
  --template-file infra/main.bicep `
  --parameters infra/parameters/pre.bicepparam
```

The first pass may leave `ENTRA_BFF_AUDIENCE` empty so Azure can return the final
hostnames. This is fail-closed: the BFF will not start in Entra mode with an empty
audience. After completing `phase-4-entra-configuration.md`, reapply configuration:

```powershell
$env:ENTRA_BFF_AUDIENCE = 'api://<BFF-APPLICATION-CLIENT-ID>'

az deployment group what-if `
  --subscription 8b72e64a-ae1a-4ac3-9960-dda8ee63d59e `
  --resource-group rg-common-core `
  --name apim-portal-pre-configured `
  --template-file infra/main.bicep `
  --parameters infra/parameters/pre.bicepparam

az deployment group create `
  --subscription 8b72e64a-ae1a-4ac3-9960-dda8ee63d59e `
  --resource-group rg-common-core `
  --name apim-portal-pre-configured `
  --template-file infra/main.bicep `
  --parameters infra/parameters/pre.bicepparam
```

Expected outputs are `spaHostname`, `spaHttpsUrl`, `bffHostname`, `bffHttpsUrl`,
`bffManagedIdentityPrincipalId`, and `apimReaderRoleAssignmentId`.

The deployment principal needs resource creation permissions in
`rg-common-core` and `Microsoft.Authorization/roleAssignments/write` at the exact
APIM resource scope. A practical split is Contributor on the resource group plus
User Access Administrator or Role Based Access Control Administrator on only the
APIM service. Keep approval and execution identities separate where policy
requires it.

## Runtime configuration

The Bicep template sets these BFF App Service settings:

- `ASPNETCORE_ENVIRONMENT=Production`
- `AUTHENTICATION_MODE=Entra`
- `ENTRA_TENANT_ID=3b6f65fd-e602-4e25-a81a-eb5ef7376512`
- `ENTRA_BFF_AUDIENCE=<BFF Application ID URI>`
- `APIM_SUBSCRIPTION_ID=8b72e64a-ae1a-4ac3-9960-dda8ee63d59e`
- `APIM_RESOURCE_GROUP=rg-common-core`
- `APIM_SERVICE_NAME=apim-cmn-core`
- `Cors__AllowedOrigins__0=<exact Bicep SPA HTTPS URL>`
- Application Insights and operational settings generated by the deployment

The frontend variables are public build inputs, not secrets:

- `VITE_AUTH_MODE=entra`
- `VITE_ENTRA_CLIENT_ID=<standalone SPA client ID>`
- `VITE_ENTRA_TENANT_ID=3b6f65fd-e602-4e25-a81a-eb5ef7376512`
- `VITE_BFF_SCOPE=api://<BFF-APPLICATION-CLIENT-ID>/access_as_user`
- `VITE_BFF_BASE_URL=<bffHttpsUrl output>`
- `VITE_APIM_PORTAL_URL=https://apim-cmn-core.developer.azure-api.net/`
- `VITE_APIM_GATEWAY_URL=https://apim-cmn-core.azure-api.net/`
- `VITE_DOCS_CLIENT_ID=76e21c21-a10d-45c2-ac0f-3d4e240a228c`
- `VITE_DOCS_TENANT_ID=3b6f65fd-e602-4e25-a81a-eb5ef7376512`
- `VITE_DOCS_REDIRECT_BASE_URL=<spaHttpsUrl output>`

Vite embeds these values at build time. Adding them only as Azure Static Web
Apps runtime application settings does not alter already-built JavaScript. Set
them in the GitHub `PRE` environment and rebuild whenever they change. The Vite
build also renders the exact BFF and APIM gateway origins into the deployed
`staticwebapp.config.json` CSP; the checked-in file remains hostname-neutral.

## GitHub PRE environment

Create a protected GitHub environment named `PRE`. Configure these environment
variables:

| Variable | Value |
| --- | --- |
| `AZURE_CLIENT_ID` | OIDC deployment app/service-principal client ID |
| `AZURE_TENANT_ID` | `3b6f65fd-e602-4e25-a81a-eb5ef7376512` |
| `AZURE_SUBSCRIPTION_ID` | `8b72e64a-ae1a-4ac3-9960-dda8ee63d59e` |
| `AZURE_RESOURCE_GROUP` | `rg-common-core` |
| `AZURE_STATIC_WEB_APP_NAME` | approved SPA resource name |
| `AZURE_WEBAPP_NAME` | approved BFF resource name |
| all `VITE_*` values above | final PRE public identifiers and URLs |

No GitHub secret, client secret, publish profile, ARM token, or Static Web Apps
deployment token is stored. The workflows use GitHub OIDC. Configure a federated
credential with issuer `https://token.actions.githubusercontent.com`, audience
`api://AzureADTokenExchange`, and subject
`repo:<GITHUB-ORGANIZATION>/<REPOSITORY>:environment:PRE`.

Grant the workflow identity only the deployment permissions it needs. The BFF
workflow needs deployment permission on the BFF web app. The frontend workflow
also needs `Microsoft.Web/staticSites/listSecrets/action` on the exact Static Web
App because it retrieves and masks the SWA deployment token at run time. Website
Contributor scoped separately to each target resource is the practical built-in
choice; a reviewed custom role can be narrower. It does not need APIM data-plane
or management-plane access.

The Static Web Apps deployment token is still a resource credential even though
it is never persisted in GitHub. If organizational policy prohibits retrieving
it, approve a supported alternative deployment mechanism before enabling the
frontend workflow.

## Deployment validation

After both applications are deployed and Entra configuration is reconciled, run:

```powershell
pwsh ./scripts/Test-DeveloperPortalDeployment.ps1 `
  -SpaUrl 'https://<SPA-HOST>' `
  -BffUrl 'https://<BFF-HOST>'
```

The script performs unauthenticated availability, header, physical OAuth asset,
history fallback, CORS, and fail-closed API checks. It does not validate an
authenticated catalog or APIM OpenAPI export; those require a representative
test user and are a separate smoke-test gate.

## Recommended sequence

1. Obtain human approval for names, region, SKUs, access model, and costs.
2. Create/configure the GitHub OIDC deployment identity and PRE environment.
3. Run Bicep what-if and have the exact APIM role assignment reviewed.
4. Bootstrap Azure resources and record the Bicep outputs.
5. Perform the manual Entra steps in `phase-4-entra-configuration.md`.
6. Set `ENTRA_BFF_AUDIENCE`, re-run Bicep what-if, and reapply the template.
7. Run the BFF workflow, then the frontend workflow.
8. Run the validation script and authenticated functional smoke tests.
9. Keep the managed APIM portal available; expose PRE to pilot users only after
   security and product owners approve the evidence.
